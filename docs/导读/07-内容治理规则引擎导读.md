# 07 — 内容治理规则引擎（botmaker / scarecrow / botmaker-rules）

本篇讲清楚 X 的**内容治理规则引擎**是怎么运作的：规则长什么样、怎么被编译成可执行代码、运行时如何对一条帖子/账号求值、scarecrow 如何把标签实时打出去、`botmaker-rules/` 里的规则如何被加载。

> 所有结论均来自仓库代码，括号内为源文件路径，可自行核对。规则**动作函数的具体实现**中有一部分（如 `SetTweetRtfApplyLabelWithExpirationMs`）在本开源切片里只见到调用、未见定义，文中如实标注；`.bot` 文本 → `BotMakerRule` thrift 的加载器（`botmaker_loader`）不在此切片内，加载侧也如实说明。

## 1. 一句话定位

`botmaker` 是一套**规则即代码（Rule-as-Code）**的 DSL + 编译器 + 运行时：治理团队用一份类 Scala 的 DSL 写出"什么条件下对什么对象施加什么动作"，引擎把它编译成带类型检查的可执行 `Extractor`，在事件到来时求值，动作主要是给帖子/账号**打安全标签**（RTF label）、改 `ResponseCode`、写下游服务。这些标签随后进入**可见性过滤**（`visibility-filtering` 模块）与下游消费，从而直接影响推荐内容的曝光——这就是它在推荐系统中的位置。

`scarecrow/` 是这套引擎在 X 安全场景（spam / NSFW / abuse）的具体装配：`ScarecrowBotMaker` 继承 `BotMaker` 并提供全套动作函数与下游服务注册；`botmaker-rules/scarecrow/` 里存放真正生效的规则文本（`.bot`）与派生特征（`.df`）。

## 2. 目录结构与职责

| 路径 | 语言 | 职责 |
|---|---|---|
| `botmaker/src/antlr/BotMaker.g` | ANTLR (Java target) | DSL 文法，定义词法/语法与 AST 节点类型 |
| `botmaker/src/java/com/twitter/botmaker/compiler/` | Java | **编译器**：`Parser`、`Compiler`、`CompilerContext`、`Fingerprint`、类型系统 `types/`、内建函数 `function/` |
| `botmaker/src/scala/.../rule/` | Scala | 规则容器与求值：`BotMaker`(入口)、`RuleContainer`、`RuleEvaluator`、`EventContext`、`EventOutput`(各类输出收集器) |
| `botmaker/src/scala/.../loader/` | Scala | `Loader`(取规则包) + `Scheduler`(定时刷新重编译) |
| `botmaker/src/scala/.../runtime/` | Scala | 运行时基础设施：`TwitterRuntime`、`ServiceContainer`、内建动作函数（`IncrementStat` 等） |
| `scarecrow/` | Scala | 安全场景装配：`ScarecrowBotMaker`、`ScarecrowRuntime`、各下游 `Registry`（ActionIntake / Gizmoduck / TweetService / Model …） |
| `botmaker-rules/scarecrow/bot/*.bot` | 文本 | 真正生效的规则（如 `GroxTweetProcessor.bot`、`BBQDuplicateTextProd.bot`） |
| `botmaker-rules/scarecrow/derived-feature/*.df` | 文本 | 可复用的派生特征（如 `GetTweetOrNull.df`） |

注意一个反直觉点：**编译器主体是 Java 而非 Scala**（`botmaker/src/java/.../compiler/Compiler.java` 1617 行），Scala 侧主要是运行时与装配。

## 3. 规则 DSL 长什么样

### 3.1 一条规则（`.bot`）的字段

以 `botmaker-rules/scarecrow/bot/GroxTweetProcessor.bot` 为例，规则文本是 YAML 风格的键值：

```
id: '25026'
description:\nevent: health_side_effect
condition: |
  Exists(userId) && Exists(spamScore) && Exists(postId) &&
  healthSideEffectSubEvent == "groxScore" && spamScore >= 0.97 &&
  !IsTestUser(userId)
action: |
  {
    val :tweet = GetTweetOrNull(postId);
    val :conversationId = :tweet.core_data.conversation_id;
    ...
    if (!:replyFromConvAuthor && !:highPageRank...) {
      SetTweetRtfApplyLabelWithExpirationMs("RISKY_HIGH_VIZ_REPLY", postId, CurrentTimeMs()+(OneDayInMillis*14));
    } else { Log(...); }
  }
expiry: '2029-06-14T01:10:58.669Z'
isActive: 'true'
owner:\nactionLimits: {}
```

字段含义（映射关系在 `RuleContainer.compile`：`condition→booleanExpression`、`action→actionExpression`、`event→eventType`，见 `botmaker/src/scala/.../rule/RuleContainer.scala:208-228`）：

| 字段 | 含义 | 约束（代码侧） |
|---|---|---|
| `id` | 规则唯一 ID | 重编译等价判断用 `id+name+eventType+action/booleanExpression+actionLimits`（`RuleContainer.scala:119`） |
| `event` | 触发的事件类型 | 决定这条规则挂在哪个 `EventEvaluator` 下 |
| `condition` | 布尔表达式 | 编译期强制返回类型必须是 `Boolean`（`RuleContainer.scala:220` 的 `isDivergentTo(Type.BOOLEAN,...)` 检查） |
| `action` | 动作块（类 Scala 语句块） | 由 `val`/`if`/`for`/函数调用组成，主要做副作用 |
| `expiry` / `isActive` | 有效期 / 是否启用 | 由加载侧解释 |
| `actionLimits` | 动作限流配置 | 运行时按 `ActionLimit`(`periodInMinutes`/`quota`/`strategy`) 限流（`ScarecrowBotMaker.applyActionRateLimit`） |

### 3.2 文法能表达什么

`BotMaker.g` 定义的 token 给出了 DSL 的全集：`&&`/`||`(CONJUNCTION/DISJUNCTION)、`!`(NEGATE)、`< <= > >= == !=`(关系)、`+ - * / %`(算术)、`MATCHES`(正则)、`(...)` 类型转换 CAST、字段访问 `a.b`(ACCESSOR/INDEX)、函数调用 `f(...)`(FUNCTION)、`val`(VAL)、`if/else`(IF)、`{...}`(BLOCK)、`for`/`FOREACH`(FOREACH)、`flatmap`、`with`、`import`、`param(params(...)` 签名)。标识符体系：`FEATURE`(裸名如 `spamScore`)、`VARIABLE`(`:` 前缀如 `:tweet`)、`SYMBOL`(反引号 `` `AutoExpiringTempSkipList` ``)、`FIELD`(`.` 后缀)。

### 3.3 派生特征（`.df`）

`.df` 是可被规则当函数调用的"命名表达式"。`botmaker-rules/scarecrow/derived-feature/GetTweetOrNull.df`：

```
description:\nexpression: |
  params(Long :tweetId) {
    TryOrElse(GetTweet(:tweetId), (com.twitter.tweetypie.thriftjava.Tweet)NULL)
  }
logged: 'false'
returnType: Auto
```

它有参数签名 `params(...)`、返回类型可 `Auto` 推导，编译后进入 `DerivedFeatureContainer`，规则里直接按名字调用（编译期生成 `DerivedFeatureCall`）。

## 4. 编译链路

```
.bot / .df 文本
   │  (加载器 botmaker_loader 不在本切片：文本 → BotMakerRule / BotMakerDerivedFeature thrift)
   ▼
BotMakerRulesPackage(thrift: rules + derivedFeatures)
   │  BotMaker.State.compile()  BotMaker.scala:405
   │   - Fingerprint.of(pkg) 相同则整包跳过重编译  BotMaker.scala:407
   │   - 规则按 eventType 分流：config / system(以 system_ 前缀) / regular
   ▼
RuleContainer.apply()  RuleContainer.scala:134
   │  逐条 RuleContainer.compile()  RuleContainer.scala:192
   │    context.compile(booleanExpression) → booleanAst (ASTNode)
   │    context.compile(actionExpression)  → actionAst   (ASTNode)
   │    编译失败 → FakeEvaluator(标记 hasCompilingFailure，运行期直接 ABORTED)
   ▼
CompiledEvaluator(rule, booleanExtractor, actionExtractor)  RuleEvaluator.scala:106
   │  ASTNode.toExtractor → Extractor（带 fingerprint / cacheLevel）
   ▼
运行时 Context.run(extractor) 求值
```

关键实现点：

1. **解析在 `Parser.java`**：`Parser.createParseTree` 用 ANTLR 的 `BotMakerLexer`+`BotMakerParser` 把字符串变成 `Tree`（`Parser.java:26`）。
2. **编译在 `CompilerContext.compile`**：把 AST `Tree` 递归降为 `ASTNode`（Java 侧 `Compiler.java`/`CompilerContext`），再 `toExtractor` 得到真正可执行的 `Extractor`。`Compiler` 通过 `addPackage(...)` 注入可用函数命名空间（如 `com.twitter.botmaker.function`、`scarecrow.legacy`）。
3. **整包指纹跳过重编译**：`Fingerprint.of(rulesPackage)` 不变则 `compile` 返回 `None`、`load` 只 `loadSkip.incr()`（`BotMaker.scala:407-410`）。单条规则也做等价缓存：`areEquivalent` 比对 `id/name/eventType/actionExpression/booleanExpression/actionLimits`，相同则复用旧 `Node`（`RuleContainer.scala:119`）。
4. **提取器缓存分级**：`RuleContainer.CacheableExtractorSetter` 按 `ASTNode.CacheLevel` 把每个 `Extractor` 标为 `Global`(跨事件可缓存)/`Event`(本次事件内可缓存)/不可缓存；`Constant/Variable/InputFeature/Val/Exists/CacheGet` 显式跳过缓存（`RuleContainer.scala:274-326`）。

## 5. 运行时求值与动作分级

一次事件求值入口是 `BotMaker.checkEvent` → `State.checkEvent` → `EventEvaluator` → 该事件下每条 `CompiledEvaluator.run`（`RuleEvaluator.scala:120`）：

```
对每个 rule:
  run(booleanExtractor)
    ├─ TRUE  → context.result = VIOLATED → 接着 run(actionExtractor)   ← 只有命中才跑动作
    ├─ FALSE → context.result = UNVIOLATED → 跳过动作
    └─ 抛异常 → 按 ExceptionCategory 归类：
         Ignorable → ABORTED_IGNORED / FAILED_IGNORED（Debug 级日志）
         Interruption → 直接异常
         其它       → ABORTED（条件期）/ FAILED（动作期），动作失败仍计一次 VIOLATED
  整条带 timeout：raiseWithin(timer, timeOutDuration) 超时 → CANCELLED 并 cancel 子调用
```

`RuleResult` 全集（`EventOutput.scala` 的 `RuleResultOutput`）：`VIOLATED / UNVIOLATED / ABORTED / ABORTED_IGNORED / CANCELLED / FAILED / FAILED_IGNORED / SKIPPED`。这些结果被汇总成 `violatedRules / unviolatedRules / abortedRules / ...` 集合，供系统事件与可观测性使用。

**动作分级（ActionLevel，`ActionLevel.java`）**：每条动作函数声明自己的 `actionLevel`，用于统计"对用户的影响面"与限流粒度：

```
UNDOCUMENTED, RESERVED_FOR_DERIVED_FEATURE, NO_ACTION,
PROD_TANGIBLE_IMPACT_ACTION,      // 实体影响，如打标签
PROD_AGENT_WORKFLOW_ACTION,       // 送审/工单
PROD_OTHER_ACTION,
RESPONSE_CODE_NO_CHANGE_ACTION,   // 仅内部记录
RESPONSE_CODE_CHANGE_BEHAVIOR_ACTION  // 改变对外响应
```

`BotMaker.isUserImpacting` 把 `PROD_TANGIBLE_IMPACT_ACTION / PROD_AGENT_WORKFLOW_ACTION / PROD_OTHER_ACTION / RESPONSE_CODE_CHANGE_BEHAVIOR_ACTION` 算作"影响用户"，并按 `ruleId` 打 `user_impact.by_rule` 计数器（`BotMaker.scala:1055`）。

**动作的产出命名空间**（`EventOutput.scala` 与各 `OutputCollector`）：动作函数通过 `addOutputFeature(namespace, ...)` 写入不同通道——

| 命名空间 | 内容 | 用途 |
|---|---|---|
| `OutputFeature` | `outputFeatures` / `debugOutputs` | 规则产出的特征 |
| `RuleResult` | `violatedRules` 等集合 | 命中结果汇总 |
| `ResponseOutput` | `ResponseCode` / `finalRuleResponse` | 改变对外响应码 |
| `DerivedFeature` | `derivedFeatures` | 派生特征结果 |
| `FailureOutput` | `ruleExceptions` | 异常留痕（异常类型/信息/栈） |
| `RecordedActionOutput` / `BotUserActionOutput`（scarecrow 侧） | `recordedActions` / `botUserActions` | 记录已施加动作，防重复 |

## 6. scarecrow 与 botmaker-rules 的衔接

**规则加载（实时刷新）**：`BotMaker` 构造时建一个 `Scheduler` + `Schedule(loader, refreshDelay, retries)`（`BotMaker.scala:663`）。`Scheduler` 周期性调用 `loader.load()` 取回 `BotMakerRulesPackage`，再走 `State.compile`（`Scheduler.scala` 的 `start()` 用 `refreshDelay` 循环 reload）。因此 `botmaker-rules/` 里的 `.bot`/`.df` 一旦更新并被加载器取回，引擎会**带指纹跳过重编译地热更新**——这是治理规则能"线上改、秒级生效"的基础。`.bot` 文本如何被读成 `BotMakerRule`、存在哪（Manhattan/Strato）由本切片未包含的 `botmaker_loader` 负责，文中不臆测。

**scarecrow 把标签真正打出去**：`ScarecrowBotMaker.checkAppEvent` 同步跑 `eventType` 与其 `_async` 变体（`ScarecrowBotMaker.scala:419-440`）。动作函数本体在 `scarecrow/function/` 与 `scarecrow/legacy/` 的各 `Registry` 里。例如 `TweetRtfApplyLabel`（`scarecrow/function/ActionIntakeServiceRegistry.scala:21`）：

```
object TweetRtfApplyLabel extends FunctionUnit2O11[...] {
  override def actionLevel = PROD_TANGIBLE_IMPACT_ACTION
  override def cacheLevel  = ASTNode.CacheLevel.Event
  override def downstreams = Set(DownstreamServices.ActionIntakeService)
  // 内部调用 fetcher20.actionIntakeServiceFetcher.applyTweetLabels(...)
}
```

即规则里一句 `TweetRtfApplyLabel("COPYPASTA_SPAM", :tweetId)`，最终走 `ActionIntakeService` 的 `AddLabelsV2` 把 RTF 安全标签写到帖子元数据上；该标签随后被**可见性过滤**与下游消费，影响推荐曝光。动作还带 `downstreams` 声明与 `actionLevel`，运行期据此做限流（`applyActionRateLimit`，按 `ActionLimit` 的 `periodInMinutes`/`quota` 控制）。

**派生特征的衔接**：`.df` 编译进 `DerivedFeatureContainer`，运行时规则按名调用；同时 `DerivedFeatureOutput`/`DerivedFeatureData` 收集结果，形成"特征→规则→标签"的闭环。

## 7. 可以带走的工程经验

1. **规则与代码彻底分离**：治理逻辑写成 `.bot`/`.df` 文本，由同一套编译器保证类型安全，非工程师也能在 DSL 内表达策略，且能热更新（指纹跳过重编译）。
2. **编译期强类型 + 运行期容错解耦**：条件必须返回 `Boolean`、动作失败不连坐条件、异常按 `Ignorable/Interruption/Normal` 分级处理并保留 `FAILED_IGNORED` 等灰度态，单条规则崩了不影响整包。
3. **动作分级与影响面统计**：`ActionLevel` + `isUserImpacting` 让"打标签/送审/改响应码"各有计数，治理动作对真实用户的影响可量化、可审计。
4. **细粒度缓存分级**：`Global / Event / none` 三级 `cacheLevel` 把"常量、单事件内重复计算、不可缓存"区分开，标签这种重下游调用（`TweetRtfApplyLabel` 自带 `Event` 级缓存且注释提示"可能耗时数秒，建议 `DoAsync"`）得以控成本。
5. **可观测性内建**：每条规则产出 `violated/aborted/failed/timeout` 计数器、`RuleResult` 集合、`ruleExceptions` 栈、`user_impact.by_rule`——"为什么被打标/为什么规则没生效"在架构层就有答案。
6. **事件 + 异步双跑**：`eventType` 与 `eventType_async` 并行求值（`ScarecrowBotMaker.scala:419`），把快路径与慢副作用分开，慢动作不阻塞主链路。
